# GPU 파티클 기초 시스템

> CPU 수만 개 병목 → GPU 수십만 개 병렬 처리로 전환

---

## 핵심 내용

- **ConsumeAppend Buffer**: GPU에서 lock-free로 파티클 인덱스 관리
- **Dead/Alive Index 패턴**: 사망한 파티클 인덱스를 재활용하여 메모리 효율 극대화
- **DrawInstancedIndirect**: GPU가 직접 인스턴스 수를 결정 → CPU readback 불필요

## WHY

- CPU 파티클: 수만 개에서 **CPU 병목** 발생 (직렬 처리 한계)
- GPU 파티클: Compute Shader로 **수십만 개를 동시에** 시뮬레이션
- Indirect Drawing으로 GPU가 **자체적으로 드로우 인자 결정** → CPU-GPU 라운드트립 제거

---

## 시각화 레이아웃 — Dead/Alive 인덱스 흐름도 (3단계)

```
[Spawn 단계]
┌─────────────┐         ┌─────────────┐
│ Dead List   │─Consume→│ 새 파티클   │─Append→┌─────────────┐
│ [5,3,8,1,7] │         │ 초기화      │        │ Alive List  │
└─────────────┘         └─────────────┘        │ [5,3,8]     │
                                                └──────┬──────┘
[Simulate 단계]                                        ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────────────┐
│ Read Alive  │────▶│ 물리 시뮬   │────▶│ 생존: Write Alive   │
│ [5,3,8]     │     │ (중력,노이즈│     │ [5,8]               │
└─────────────┘     │  수명 감소) │     │ 사망(3): Dead에 반환│
                    └─────────────┘     └──────┬──────────────┘
[Render 단계]                                   ▼
┌───────────────────────────────────────────────────────────────┐
│ DrawInstancedIndirect — GPU가 인스턴스 수(2) 직접 결정       │
│ CPU readback 없음!                                           │
└───────────────────────────────────────────────────────────────┘
```

- 3단계를 **세로로 배치**, 각 단계에 배경색 구분 (Spawn=초록, Simulate=파랑, Render=주황)
- Dead List → Consume → Alive List 화살표에 **"원자적(Atomic)"** 라벨
- 사망 파티클(3)은 **빨간 화살표**로 Dead List에 반환되는 흐름 표시
- 최하단 Render 블록에 "CPU readback 없음!" **볼드 강조**

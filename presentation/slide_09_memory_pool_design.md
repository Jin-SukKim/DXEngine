# Memory Pool: 문제와 설계

> 시스템마다 개별 버퍼 → 하나의 통합 GPU 버퍼로 전환

---

## 핵심 내용

- **문제**: 이미터마다 별도 GPU 버퍼 생성 → 메모리 낭비 + 버퍼 생성/해제 오버헤드 + 배치 렌더링 불가
- **해결**: 하나의 대형 GPU 버퍼를 **블록 단위로 할당/해제**하는 메모리 풀
- **PoolHandle**: 시작 오프셋, 블록 수, 캐시 키를 담은 경량 핸들

## WHY

- 개별 버퍼 방식은 **메모리 단편화**가 심하고, 버퍼 생성/해제 자체가 GPU 오버헤드
- 통합 버퍼는 **하나의 SRV**로 모든 이미터의 파티클에 접근 가능
- 이것이 **배치 렌더링의 전제 조건** — 같은 버퍼에 있어야 하나의 Draw Call로 묶을 수 있음

---

## 시각화 레이아웃 — Before vs After (슬라이드 좌우 분할)

```
[Before: 개별 버퍼]                  [After: 통합 메모리 풀]
┌──────────┐ GPU Buffer 1           ┌──────────────────────────────┐
│ System A │ Particle[512]           │        통합 GPU Buffer       │
│ 512개    │ Alive[512]             │┌────┬────┬────┬────┬────┬───┐│
│ 버퍼 6개 │ Dead[512]              ││ A  │ B  │빈 │ C  │ D  │...││
└──────────┘ Emitter[1]             │└────┴────┴────┴────┴────┴───┘│
┌──────────┐ GPU Buffer 2           │  블록 단위 할당/해제         │
│ System B │ Particle[1024]          │                              │
│ 1024개   │ Alive[1024]            │  PoolHandle:                 │
│ 버퍼 6개 │ Dead[1024]             │  ├─ particleOffset: 시작위치 │
└──────────┘ Emitter[1]             │  ├─ blockCount: 블록 수      │
┌──────────┐ GPU Buffer 3           │  └─ bakedPosKey: 캐시 키     │
│ System C │ ...                     └──────────────────────────────┘
└──────────┘

문제:                                장점:
✗ 메모리 낭비                        ✓ 메모리 재사용 (생성/해제 없음)
✗ 버퍼 생성/해제 오버헤드            ✓ 모든 파티클이 같은 버퍼
✗ 배치 렌더링 불가                   ✓ 배치 렌더링 가능!
                                       (→ Slide 12-13 연결)
```

- **좌측(Before)**: 빨간 배경, 시스템별 독립 버퍼 박스 3개 + 문제점 ✗ 리스트
- **우측(After)**: 초록 배경, 하나의 긴 버퍼 박스 내부에 색상별 블록 + 장점 ✓ 리스트
- 좌측에서 우측으로 **큰 화살표** + "통합" 라벨
- 우측 하단에 PoolHandle 구조를 **작은 박스**로 표시
- "배치 렌더링 가능!" 옆에 **Slide 12-13 참조 링크** 표시
